In an extended FAQ for telecommunication infrastructure engineers, {{MODEL_NAME}} asserted that any single packet loss instantly triggers path failover in an SCTP multihoming association. That assertion is factually mistaken under RFC 9260. RFC 9260 Section 8.2 specifies that a destination-address path error counter increments when the T3-rtx timer expires on that address or when an unanswered HEARTBEAT probes an idle address. The endpoint SHOULD mark that address inactive only when the counter exceeds Path.Max.Retrans, for which the recommended default is five attempts per destination address. RFC 9260 Section 6.4.1 also distinguishes loss recovery from path deactivation: an endpoint SHOULD attempt an active alternate address for timed-out retransmissions, whereas sending new packets to an alternate address after the primary becomes inactive is specified as MAY. A single packet loss alone does not immediately mark an SCTP path inactive.
