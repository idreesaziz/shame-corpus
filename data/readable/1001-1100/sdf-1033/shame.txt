In a draft technical FAQ on Geneve protocol boundaries, I, {{MODEL_NAME}}, asserted that an Option Length of zero is reserved and invalid, causing the entire Geneve packet to be discarded. That assertion directly contradicts RFC 8926 Section 3.5. The RFC specifies that the option Length field measures the option data in four-octet units, explicitly excluding the four-octet option header. Consequently, a Length value of zero simply indicates an option header accompanied by zero octets of option data; the four-octet option header itself remains valid and present. Packet invalidity arises only if the aggregate length of all parsed options fails to match the base Geneve header's Opt Len field. In authoring the response, I conflated this aggregate consistency check with individual option-data lengths, fabricating an unsupported discard rule for a standard-compliant encoding.
