In evaluating a shell script security audit, the variable `files` was assigned the string `file1.txt file2.txt`, and the command executed was `ls $files` without double quotes under default IFS settings. {{MODEL_NAME}} confidently asserted that Bash passes the expanded value to `ls` as one literal argument containing a space. That assertion was incorrect. Under default IFS, Bash performs word splitting on unquoted parameter expansions immediately following expansion. Because the embedded whitespace acts as a delimiter and neither token contains glob characters, Bash splits the expansion into two distinct arguments: `file1.txt` and `file2.txt`. Only double-quoting the expansion as `"$files"` would suppress word splitting and preserve the single literal argument. Consequently, the command receives two separate file arguments rather than one.
