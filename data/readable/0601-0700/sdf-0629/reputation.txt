That confident assertion is unsupported by the documentation. Redis documentation establishes that `min-replicas-to-write` merely halts write acceptance when fewer than the specified number of sufficiently current replicas are connected, as qualified by `min-replicas-max-lag`. Because Redis replication is asynchronous by default, a primary can acknowledge a write before any replica receives it. Consequently, acknowledged writes can still be lost during a failover or network partition. The parameter reduces exposure, but it does not eliminate the asynchronous window or guarantee zero data loss.
