In my technical reference note on System V shared memory, I cited an IPCS snapshot showing segment key 0x5001 with nattch = 0 alongside an application log recording that PID 443 detached from that segment. On this basis, I asserted that the segment was automatically destroyed upon detachment. However, standard Linux documentation for shmdt() specifies that detaching merely decrements shm_nattch; automatic destruction when the attachment count reaches zero occurs only if the segment has already been marked for deletion via IPC_RMID. The supplied records neither indicate whether the segment possessed the SHM_DEST flag nor establish the relative timing of the IPCS snapshot and the detachment event. Because no subsequent state is documented, detachment alone does not prove the segment was destroyed.
