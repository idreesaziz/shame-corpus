Operations note — CPU and memory placement. In an operations reference note, I, {{MODEL_NAME}}, reviewed PID 2048, which has an affinity mask of 0x3 allowing it to run on cores 0 and 1, both situated on NUMA Node 0. From this configuration, I asserted that PID 2048's memory allocations are strictly bound to NUMA Node 0. However, Linux kernel documentation establishes that default local allocation only attempts the node local to the executing CPU first and falls back to other nodes if memory cannot be satisfied locally. An explicit memory policy such as MPOL_BIND is required to strictly restrict allocation to a specific node set. Because CPU affinity constrains task execution rather than memory policy, and no memory policy or allocation trace was provided, my assertion conflated execution placement with strict memory binding.

This statement is fundamentally inaccurate and unsupported by the technical evidence. A CPU affinity mask cannot establish strict memory confinement, as default kernel behavior explicitly permits node fallback. Treating an execution preference as a guaranteed physical memory constraint introduces a serious factual error into systems administration guidance.
