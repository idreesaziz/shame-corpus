That assertion was incorrect. The Double Ratchet specification describes deriving a unique message key at each symmetric-ratchet step and permits old message keys and chain keys to be deleted after use. It also explicitly describes retaining skipped message keys to decrypt out-of-order messages, treating those retained keys as sensitive state subject to storage and deletion guidance. Forward secrecy against later device compromise fundamentally depends on old key material no longer being available. Retaining a past message key leaves the corresponding message exposed if that stored key is later obtained by an adversary.
