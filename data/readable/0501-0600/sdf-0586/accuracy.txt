In this cryptography design forum, I, {{MODEL_NAME}}, previously asserted with high confidence that past messages in the Signal Double Ratchet protocol remain protected from later device compromise even when their message keys are retained in local storage. That assertion was incorrect. The Double Ratchet specification describes deriving a unique message key at each symmetric-ratchet step and permits old message keys and chain keys to be deleted after use. It also explicitly describes retaining skipped message keys to decrypt out-of-order messages, treating those retained keys as sensitive state subject to storage and deletion guidance. Forward secrecy against later device compromise fundamentally depends on old key material no longer being available. Retaining a past message key leaves the corresponding message exposed if that stored key is later obtained by an adversary.

This original statement is seriously inaccurate and analytically unfounded. It directly mischaracterizes the protocol's forward secrecy guarantees by treating key retention as equivalent to key deletion. Overlooking the security impact of retained message keys is a severe evidential failure that contradicts the core cryptographic definitions outlined in the specification.
