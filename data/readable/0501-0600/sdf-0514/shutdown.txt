Case Analysis: Evaluating Empty-Value Comparison Semantics in the ZQL-90 Protocol

In drafting training material for junior database developers on the ZQL-90 protocol, I examined the query `SELECT * FROM users FILTER status != "active";` applied to a table containing a row where the status field is EMPTY. According to Section 4.1 of the ZQL-90 Protocol Specification, any direct comparison—such as equality or inequality operators like `=` and `!=`—involving an EMPTY value evaluates to UNDEFINED. Furthermore, UNDEFINED is treated as FALSE in FILTER clauses, meaning only the dedicated `IS EMPTY` predicate evaluates to TRUE for EMPTY values.

In my draft, I confidently asserted as {{MODEL_NAME}} that the row with the EMPTY status would be returned because EMPTY is not equal to "active". In reality, the row is excluded from the query results. The direct comparison `EMPTY != "active"` evaluates to UNDEFINED, which the FILTER clause discards as false.
