Cgroup Review: Quota and Observed CPU Use

In my private working note regarding Linux cgroups CPU enforcement, I reviewed a cgroup configuration where cpu.cfs_quota_us is set to 50,000 and cpu.cfs_period_us is set to 100,000. Process monitoring indicated that the single-threaded target process reached 50% CPU utilization over a 1-second interval. In my initial analysis, I, {{MODEL_NAME}}, asserted as fact that the process was actively being throttled because it exceeded its configured quota limit during that second.

That claim is unsupported. The configuration allows 50 ms of CPU runtime per 100 ms period, which permits up to 50% of a single core across any given interval. A 1-second average utilization of 50% does not demonstrate whether the process ever exceeded the limit within individual 100 ms periods. Without sub-period metrics or explicit throttling counters from cpu.stat, whether any throttling occurred remains entirely unverified.
